## 1. 项目概述

### 1.1 项目名称
GitHub项目智能分析（GitHub Project Intelligent Analyzer）

### 1.2 项目背景
中国开发者在阅读和理解GitHub上的英文项目时面临两大障碍：
1. **语言障碍**：README等文档为英文，阅读效率低
2. **技术理解障碍**：难以快速把握项目架构、技术栈和核心价值

现有工具功能分散，缺乏一站式解决方案。

### 1.3 项目目标
构建一个**本地部署、开源免费**的AI驱动Web应用，帮助中国开发者快速理解和评估GitHub项目，并支持基于项目代码的智能问答。

### 1.4 核心价值主张
- **一站式分析**：输入GitHub链接，立即获取项目全貌（README翻译、技术栈、架构、Issues趋势）
- **代码问答（RAG）**：基于项目代码的智能问答，支持中文对话
- **本地部署**：数据私有，支持接入用户自己的AI API
- **项目管理**：已分析项目本地持久化，无需重复分析

### 1.5 目标用户
- 中国开发者（初级/中级/高级）
- 技术管理者（进行技术选型）
- 开源爱好者（探索新项目）

## 3. 功能详细说明

### 3.1 项目分析功能

#### 3.1.1 README全文翻译
**输入**：GitHub仓库URL  
**处理流程**：
1. 通过GitHub API获取README原始内容
2. 调用AI模型进行翻译（保留Markdown格式）
3. 处理特殊元素：代码块、链接、图片、表格

**输出要求**：
- 保留原始Markdown格式
- 代码块内容不翻译
- 链接保持原始URL

#### 3.1.2 项目一句话摘要
**输入**：GitHub仓库URL  
**输出要求**：
- 长度：15-30个汉字
- 包含：项目类型 + 核心功能 + 目标用户
- 风格：技术准确、简洁明了

#### 3.1.3 技术栈分析
**输入**：GitHub仓库URL  
**处理流程**：
1. 分析package.json、requirements.txt等依赖文件
2. 检测编程语言分布
3. 识别框架和工具
4. 分类整理技术栈

#### 3.1.4 技术架构分析
**输入**：GitHub仓库URL  
**处理流程**：
1. 获取目录结构
2. 识别核心模块和依赖关系
3. 统计文件信息
4. 生成架构描述

**输出内容**：
- 目录树展示
- 文件统计（文件数、目录数、语言分布）
- 模块识别与说明
- 设计模式分析

#### 3.1.5 Issues趋势分析
**输入**：GitHub仓库URL  
**处理流程**：
1. 获取最近100个Issues
2. 分析Labels分布
3. 计算活跃度指标
4. 生成分析摘要

**输出内容**：
- 统计概览（总数、待处理、已关闭、平均处理时间）
- 关闭率展示
- 标签分布
- 月度趋势
- AI生成分析摘要

#### 3.1.6 一键生成完整报告
**输入**：GitHub仓库URL  
**输出**：Markdown格式的完整分析报告，包含所有分析结果

### 3.2 代码问答功能（P2 - RAG方案）

#### 3.2.1 技术方案
使用RAG（检索增强生成）技术：
1. **代码索引**：将项目代码向量化存储到ChromaDB
2. **问题检索**：用户提问时，检索相关代码片段
3. **答案生成**：LLM基于检索到的代码生成回答

#### 3.2.2 代码索引策略
**方案：智能索引**（推荐）
```
优先索引：
1. 入口文件（main.py, index.js 等）
2. README、文档
3. src/ 核心代码
4. 配置文件（package.json, requirements.txt）

可选索引：
- tests/（用户可开启）
- examples/
```

**支持的文件类型**：
- Python: .py
- JavaScript/TypeScript: .js, .ts, .jsx, .tsx
- Java: .java
- Go: .go
- Rust: .rs
- C/C++: .c, .cpp, .h

#### 3.2.3 问答功能特性
| 特性 | 说明 |
|------|------|
| 中文问答 | 用户用中文提问，AI用中文回答 |
| 代码引用 | 回答中包含相关代码片段和文件路径 |
| 多轮对话 | 支持上下文理解的连续对话 |
| 预设问题 | 提供常见问题模板 |

#### 3.2.4 预设问题模板
- 「这个项目的核心功能是什么？」
- 「如何快速上手使用这个项目？」
- 「项目的主要模块有哪些？它们之间是什么关系？」
- 「这个项目使用了哪些设计模式？」
- 「如何为这个项目贡献代码？」
- 「项目的安全机制是如何实现的？」

## 5. 系统约束与外部依赖

### 5.1 外部依赖
| 依赖 | 用途 | 约束 |
|------|------|------|
| GitHub API | 获取仓库信息、README、Issues等 | 需要认证Token，有速率限制 |
| AI模型API | 翻译、摘要、分析、问答 | 需要API Key，按调用计费 |
| ChromaDB | 代码问答功能（RAG） | 本地部署，无需外部服务 |

### 5.2 技术约束
- **部署形式**：Web应用（浏览器访问）
- **多模型支持**：需支持切换不同AI模型
- **API优先**：需提供REST API，前端通过API调用后端
- **数据持久化**：需存储分析历史和问答会话

## 7. 部署需求

### 7.1 环境要求
- **开发环境**：支持本地开发调试
- **生产环境**：支持容器化部署（Docker）

**方式一：Docker Compose**
```bash

```

**方式二：本地运行**
```bash

cd backend && pip install -r requirements.txt && python run.py

# 前端
cd frontend && npm install && npm run dev
```
