# GitHub项目智能分析 - 后端快速启动说明

## 环境要求

- Python 3.11+
- 网络连接（需要访问GitHub API和AI模型API）

## 快速启动

### 1. 进入后端目录

```bash
cd backend
```

### 2. 创建虚拟环境并安装依赖

```bash
# 创建虚拟环境
python -m venv venv

# 激活虚拟环境
# Windows:
venv\Scripts\activate
# Linux/Mac:
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

### 3. 配置环境变量

复制 `.env.example` 为 `.env`，并填入你的API密钥：

```bash
cp .env.example .env
```

编辑 `.env` 文件，填入以下必填配置：

```env
# OpenAI兼容API配置（必填）
OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxx
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini

# GitHub Token（可选，不填则限制60次/小时）
# GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
```

> **说明：** GitHub Token是可选的。不填时每小时可请求60次，个人测试足够。如需更高频率可配置Token（5000次/小时）。

### 4. 启动服务

```bash
python run.py
```

服务启动后：
- API地址：http://localhost:8000
- API文档：http://localhost:8000/docs（Swagger UI）
- 健康检查：http://localhost:8000/api/health

## 常见问题

### 1. GitHub API限流

如果遇到 `403` 错误，说明GitHub API请求频率超限。解决方案：
- 等待1小时后重试（无Token限制60次/小时）
- 或在 `.env` 中配置 `GITHUB_TOKEN` 提高到5000次/小时

### 2. AI模型调用失败

如果翻译或摘要生成失败：
- 检查 `OPENAI_API_KEY` 是否正确
- 检查 `OPENAI_BASE_URL` 是否可访问
- 确认账户余额充足

### 3. 端口被占用

如果8000端口被占用，修改 `run.py` 中的端口号：

```python
uvicorn.run(
    "app.main:app",
    host="0.0.0.0",
    port=8001,  # 改为其他端口
    reload=True
)
```

## API使用示例

### 发起分析

```bash
curl -X POST http://localhost:8000/api/analyze \
  -H "Content-Type: application/json" \
  -d '{"url": "https://github.com/facebook/react"}'
```

### 查询状态

```bash
curl http://localhost:8000/api/analyze/{id}/status
```

### 获取结果

```bash
curl http://localhost:8000/api/analyze/{id}/result
```
